ALF-286 — Composable shared skills across repos

Yes — with a small composer, not a framework: shared templates with variables and named slots, vendored into each repo, compose a committed SKILL.md.

Where we landed

Each shared skill becomes a template in oddobot-skills carrying variables and named slots. Consuming repos vendor a committed copy, supply their own vars.json and fragments, and a compose step emits a generated-but-committed SKILL.md. Insights flow back up through an inbox, with the one judgment step — integrating prose — left to a human or an LLM, never a script.

Build it as a standalone package, count which mechanisms actually fire, and revisit “is this a product” in 60 days with data. The story I’d cut next: compose refinement and implement-spec from shared templates.

The evidence

Everything below is for whoever builds on this. Acting on the answer needs only what’s above.

Why

The divergence is phrase-level, not section-level

Diffing the four candidate skills between alfred and motivic gives about ten divergences. Exactly one is a self-contained block plain concatenation could express; every other one is woven into a sentence.

Manual copying has already rotted

refinement’s What to produce list was numbered 1. then 3. — a hole left by copying between the repos, and the failure this spike exists to fix.

The generated-file trap is the sharpest risk

The compounding-learning rule has every agent edit SKILL.md the turn it hits a gotcha; a compose would silently wipe that edit. It needs three defences: a DO-NOT-EDIT banner, a recompose-diff check in check:fast, and a routing rule in compounding-learning.

Technical shape

oddobot-skills/
  skills/refinement/SKILL.md.tpl   shared prose + {{VARS}} + slots
  scripts/compose.mjs              zero-dep; vendored with the content
  inbox/<repo>/<skill>/*.md        fragments awaiting integration

alfred/.claude/
  shared-skills/                   VENDORED — never hand-edited
  skills/refinement/
    SKILL.md                       GENERATED · COMMITTED · DO-NOT-EDIT
    local/vars.json
    local/fragments/*.md

npm run skills:sync is the only writer: shallow-clone upstream, overwrite, record the SHA, recompose.

Alternatives we’re not taking

copier instead of a composer

Its copier update three-way merge assumes the output is hand-edited; ours is generated and a check fails if anyone touches it. Steal the design — answers-file as manifest, CI opening an MR when upstream moves — not the tool.

An npm git dependency

oddobot-skills is private, so every npm ci in every web container would need a GitHub token.

A git submodule

A fresh web-session clone can land with an empty directory and no skills at all — silently.

Is this a project of its own?

The plumbing is commodity — copier and cruft have kept many downstream copies in sync with a template for years. The skills-specific case is empty: anthropics/skills Discussion #380 asks for exactly this and has no maintainer response in seven months. Nobody has built it — an opening; almost nobody is asking — a thin market.

What’s genuinely new is merging prose, in both directions: every existing tool assumes structured data and flows one way. Build the composer with a real CLI boundary, instrument it, and decide with numbers.
