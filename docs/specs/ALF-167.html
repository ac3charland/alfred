ALF-167 — Add ability to auto-suggest projects for code items with leading “:”

Start an Inbox capture with a bare : and alfred drops a list of your projects under the box. Arrow to one, hit ↵, and the box becomes ALF: — ready for the title. The ALF-62 prefix parse then classifies the capture exactly as it does today; this story only makes the prefix easy to type.

1 · Context & problem

ALF-62 shipped the prefix grammar: text typed into the Inbox capture box is split at the first colon, and if the part before it matches a project's key or name (case-insensitively), the item is captured as item_type = 'code' with intended_project_id set and the prefix stripped from the title. That parse lives in frontend/lib/code/project-prefix.ts and runs only where the Inbox box opts in (<CaptureBox parseProjectPrefix />).

The gap is recall. The grammar only fires on an exact key or name, so it demands the owner remember which of them each repo carries — and it fails silently: ALFR: fix the toast or alfrd: fix the toast looks like it worked, but lands in the Inbox as a plain unclassified item with the prefix baked into its title. Nothing on screen ever offers the list of projects at the moment the prefix is being typed, and nothing tells you the prefix missed.

This story adds the missing affordance — an anchored, keyboard-driven project list under the capture box, opened by a leading : — without touching the grammar, the schema, or the API. It is a pure frontend change.

2 · Resolved scope from refinement Q&A

  • Trigger: a literal leading : opens the list. Typing an ordinary capture never summons a dropdown.
  • On select: the box's text becomes <KEY>: — plain, editable text. No chip, no hidden state; the existing ALF-62 parse stays the one and only classifier.
  • Surface: the Inbox capture box only — the same single surface that already opts into prefix parsing. Folder boxes, inline subtask boxes and the New Story dialog are untouched.

3 · Decisions locked in this refinement

D1The trigger is a leading colon, not first-word typeaheadowner

The list opens when the capture box's first non-whitespace character is :, and only then. Matching the first word of every capture against project names was considered and rejected.

Why: the capture box is the app's hero surface and most captures are not code. A dropdown that flickers open on “b” of “buy milk” taxes every capture to help a minority of them. A leading : is a deliberate gesture: it costs one keystroke, it is unambiguous, and it makes the feature's cost exactly zero for everything else.

D2The query is the first token after the colon; the rest is preserved

Everything after the leading : up to the first whitespace is the query; whatever follows is the remainder and survives selection. So :alf add dark mode still resolves to Alfred and becomes ALF: add dark mode.

Why: the alternative — treating the whole tail as the query — collapses the moment the user types the title before picking, leaving them in a dead end the parse can't rescue (:alf add dark mode has an empty candidate prefix, so it captures as unclassified). Known limit: a project whose name contains a space can't be typed in full as a query; its key still matches, and it is always reachable with ↑↓ from the unfiltered list.

D3Selection writes text, not stateowner

Choosing a project rewrites the box's value to <KEY>: <remainder>. Nothing new is stored on the component, nothing new is sent to the API, and classification still happens in parseProjectPrefix at submit time.

Why: one code path stays authoritative. The user can edit or delete the prefix by hand afterwards and the result is exactly what the text says — no invisible assignment that disagrees with what's on screen. It also means this story adds no migration, route, or store change.

D4Zero matches closes the list — there is no “no matches” panel

While the trigger holds, the popover renders only when at least one project matches. A query that matches nothing closes it; deleting back to a matching query reopens it.

Why: a bare : always lists every project, so discovery is free and the list disappearing is itself the “that's not a project” signal. The alternative leaves a dead panel hovering under the box for the whole of a capture that legitimately starts with a colon (:thinking about X) — obstructing the one surface that must never be obstructed.

D5While the list is open, ↵ selects and does not capture

↵ commits the active suggestion; Tab does the same; ↑/↓ move the active row; Esc dismisses the list for the rest of the trigger session (it re-arms once the value stops starting with :). The box's text is never cleared by Esc.

Why: the list is open only in the :query state, where submitting would capture junk (“:alf”) anyway — so ↵ has nothing valuable to override. This is the same ↑↓/↵/Esc contract the ⌘P search field and the ⌘K palette already teach.

D6The Inbox textarea becomes role="combobox", and the queries that name it are updated

When suggestions are enabled the textarea carries the full combobox wiring — role="combobox", aria-expanded, aria-controls, aria-activedescendant, aria-autocomplete="list" — keeping its aria-label="Capture box". Folder/subtask boxes are unchanged and stay textboxes.

Why: aria-expanded is not supported on textbox, so the lint gate's jsx-a11y/role-supports-aria-props rejects the half-measure — and the house pattern for this control is already a combobox. Cost, accepted: the role changes for the Inbox box, so the seven queries that ask for it by role must move to combobox (§6.5) — three in capture-box.test.tsx's prefix block and four E2E specs. The other 26 queries in that file render <CaptureBox /> without the prop and stay as they are.

D7Built from the shared layer, not a fresh dropdown

The pure filter/rank layer goes in lib/code/project-suggestions.ts beside project-prefix.ts; the panel is the Popover atom (PopoverAnchor + PopoverContent); rows reuse Badge and lib/code/project-color.ts (projectColorFor, projectBadgeClasses, projectTextClasses) with the same GitBranch glyph the ProjectNav and ⌘K palette use.

Why: a suggestion row and the chip the captured item ends up wearing (ProjectKeyChip) then share one colour rule, so “the amber one” means the same thing in both places — and the popover's chrome, portal, animation and dismissal come from the atom rather than a fourth hand-rolled panel.

D8One flag still gates both halves

Suggestions ride the existing parseProjectPrefix prop — no second prop. Its docstring is updated to say it now enables the suggestion list and the parse.

Why: the dropdown must never appear where the parse doesn't run, or it promises a classification the surface won't deliver. Keeping one flag makes that impossible to get wrong, and avoids churning both call sites and the stories for a rename.

4 · The behaviour

4.1 · The trigger grammar

The trigger is derived from the box's raw value on every keystroke — there is no “suggestion mode” to enter or leave. Leading whitespace is ignored, so a stray space before the colon still works.

Matching & order

  • A project matches when the query is a prefix or a substring of its key or its name, compared case-insensitively.
  • Ranking reuses the ladder in command-destinations.ts: prefix (0) before substring (1), taking the better of the key and name rank. Ties keep the store's order (getProjects → oldest first), which is also the order the colour palette is assigned in — so the list reads in the same sequence as the ProjectNav.
  • An empty query keeps every project in that natural order. No cap, no “+N more”: the project list is single-user small, and the panel scrolls if it ever isn't.

4.2 · What selection writes

Selection replaces the leading :query with the project's key — always the key, even when the user typed the name, because the key is the canonical, 3-char, unique form the parse prefers. The caret lands at the end of the value and focus never leaves the box.

4.4 · State machine

The whole machine is derived from the box's value plus one boolean (“dismissed”), so there is no state to keep in sync with the text — deleting back to : reopens the list exactly as typing it forward does, unless Esc dismissed this trigger session.

6.2 · The pure layer

// frontend/lib/code/project-suggestions.ts

/** The live trigger, derived from the capture box's raw value. */
export interface SuggestTrigger {
  /** Text between the leading ':' and the first whitespace — '' right after ':'. */
  query: string;
  /** Everything after the query (trimmed) — preserved through a selection. */
  remainder: string;
}

/** `:al add dark mode` → { query: 'al', remainder: 'add dark mode' }; no leading ':' → null. */
export function parseSuggestTrigger(value: string): SuggestTrigger | null;

/**
 * Projects matching `query`, best first: prefix beats substring, key and name are both
 * matched case-insensitively, and the better of the two ranks wins. Ties keep the given
 * order (the store's nav order). An empty query returns every project, unfiltered.
 */
export function rankProjectSuggestions(
  query: string,
  projects: readonly Project[],
): Project[];

/** The box's next value once `project` is chosen: `ALF: ` or `ALF: add dark mode`. */
export function applyProjectSuggestion(trigger: SuggestTrigger, project: Project): string;

/** Stable DOM id for a row's `<li role="option">` (the aria-activedescendant target). */
export function projectSuggestionDomId(project: Project): string;

The rank ladder is the one already written in command-destinations.ts (rankField: prefix → 0, substring → 1, no match → null). Lift the rule, don't invent a second one — if it's worth sharing, extract it to a common helper and adopt both call sites in the same change, per the frontend-architecture skill's rule of two.

6.3 · Wiring in the capture box

// frontend/components/tasks/capture-box.tsx (full mode only)

const trigger = parseProjectPrefix ? parseSuggestTrigger(value) : null;
const suggestions = trigger ? rankProjectSuggestions(trigger.query, projects) : [];
const suggestOpen = trigger !== null && !dismissed && suggestions.length > 0;

// Reset the active row whenever the query changes — the derive-during-render pattern
// (see search-box.tsx), never a setState effect. Clamp as the list shrinks.
// Re-arm the dismissal when the value stops starting with ':' (trigger === null).
  • Key handling extends the existing handleKeyDown: when suggestOpen, ↑/↓/↵/Tab/Esc are consumed with preventDefault() and return before the current Enter-submits branch; when it's closed the handler behaves exactly as it does today.
  • Applying a selection sets the value from applyProjectSuggestion and then puts the caret at the end. Setting selection inline is clobbered by the re-render, so flag it (a ref) and place the caret in a useLayoutEffect that runs after the value commits — the same beat the ghost-array effects already run on.
  • Anchor: the capture surface <div> becomes the PopoverAnchor, so the panel inherits the box's width via var(--radix-popover-trigger-width). The popover is non-modal and prevents onOpenAutoFocus / onCloseAutoFocus, so the textarea never loses focus; onInteractOutside ignores pointer-downs landing on the box itself. That contract is already written in search-results-popover.tsx — mirror it.
  • Ghost flourish, error text, spinner, in-flight counting and the serif prompt are untouched. A capture made through a suggestion is an ordinary capture.

6.4 · Accessibility

  • Textarea (suggestions enabled only): role="combobox", aria-label="Capture box", aria-autocomplete="list", aria-expanded={suggestOpen}, aria-controls pointing at the listbox id, aria-activedescendant set to the active row's id while open.
  • Panel: <ul role="listbox" aria-label="Projects"> with <li role="option" aria-selected> rows; glyphs are aria-hidden.
  • Rows keep focus in the field: onMouseDown is prevented, selection happens on click; hover sets the active index so pointer and keyboard never disagree.
  • Motion follows the atom (fade-in/zoom-in-95, already carrying motion-reduce:animate-none) — no new animation is introduced.

6.5 · The role change, precisely

Seven queries name the Inbox box by role and must move from textbox to combobox (D6): capture-box.test.tsx lines 329 / 353 / 375 (the parseProjectPrefix block), and one query each in e2e/inbox.spec.ts, e2e/inbox-epic.spec.ts, e2e/inbox-viewport.spec.ts, e2e/capture-ghost.spec.ts. Every other getByRole('textbox', { name: /capture box/i }) in that test file renders <CaptureBox /> without the prop and must keep passing untouched — if one of those needs editing, the role was applied too broadly.

9 · Out of scope

  • Epic suggestions. The colon suggests a project only. A pre-factory epic hint is its own ticket (see the ALF-158 epic, D11).
  • Suggesting on any other surface — folder and subtask capture boxes, the New Story dialog, the gate dialog, the POST /api/items ingest path.
  • Creating a project from the list (“no match → Create project ‘X’…”). The list only ever offers what exists.
  • Fuzzy / typo-tolerant matching (:aflred). Prefix + substring only, matching the ⌘K ladder.
  • Changing the ALF-62 grammar, the schema, or how a captured code item is classified.
  • A second trigger character for tasks, folders, or due dates.

Open questions

  • None blocking. The one deliberate limitation to watch in use: a multi-word project name can't be typed as a query (D2) — if that starts to bite, the fix is a follow-up that lets the query span spaces while the list still has matches.

10 · Acceptance criteria

  • ☐ Typing : as the first non-whitespace character of the Inbox capture box opens a listbox of every project, first row active, anchored under the box at its full width.
  • ☐ Each row shows the project's GitBranch glyph in its assigned colour, its name, and its key as a tinted mono pill; the footer reads ↑↓ navigate · ↵ insert · esc dismiss.
  • ☐ Typing after the colon filters the list: prefix matches before substring matches, key and name both matched case-insensitively, ties in store order.
  • ☐ A query with no matches closes the panel entirely — no empty panel and no “no matches” line — and deleting back to a matching query reopens it.
  • ☐ ↑/↓ move the active row and clamp at both ends; hovering a row makes it active.
  • ☐ ↵ or Tab or a click on a row rewrites the value to <KEY>: plus any remainder, leaves the caret at the end and focus in the box, and closes the panel — without capturing anything.
  • ☐ Esc closes the panel without altering the text; a following ↵ captures the text verbatim; the panel re-arms once the value stops starting with :.
  • ☐ Submitting ALF: add dark mode still produces a Code item assigned to Alfred titled “Add dark mode” — the ALF-62 path, unchanged.
  • ☐ No dropdown ever appears in a folder or subtask capture box, or for values that don't lead with a colon (Note: buy milk, buy milk), or when the project list is empty.
  • ☐ The Inbox textarea exposes the combobox ARIA of §6.4; folder/subtask boxes are unchanged.
  • ☐ Unit, RTL, Storybook and E2E coverage per §7 exists and npm run check is green.
