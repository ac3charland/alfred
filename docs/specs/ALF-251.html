ALF-251 — Redesign search to be mobile-friendly

On phones, global search moves out of the hamburger drawer. A search icon in the header opens a full-screen sheet with full-width, touch-sized, scrollable results. Desktop (⌘P field and dropdown) is unchanged.

Decisions confirmed with the human before writing: (1) The entry point is a header search icon that opens a full-screen sheet, and the field is removed from the drawer, so there is one entry point. (2) The per-group cap stays at 8 (RESULTS_PER_GROUP), with the same “+N more — keep typing” line; the pure filter layer in search-results.ts is not changed.

1. Context / problem

Ticket: “Results are small and you can’t scroll.” Both complaints come from how the phone layout of SearchBox is built today:

SymptomCause in the current code
Results are small The mobile field is inside the hamburger drawer (shell-mobile-nav.tsx, w-56 = 224px). SearchResultsPopover sets its width to var(--radix-popover-trigger-width), so on a 390px phone the results panel is about 192px wide. Titles truncate after a few words, and rows are the dense desktop py-1.5 (about 30px tall), well under the app’s 44px mobile tap target.
You can’t scroll The drawer is a modal Radix Dialog, which locks scrolling everywhere outside its own content (react-remove-scroll). The results are a Popover.Portal rendered to <body>, outside the dialog’s content, so touch and wheel scrolling on the list are blocked. The list is also capped at max-h-[70vh] and anchored below a field that already sits some way down the drawer, so with the keyboard up most of it is off-screen and can’t be reached.
Two taps before you can type You have to open the drawer, then tap the field. ShellMobileNav deliberately stops the field autofocusing when the drawer opens, because that would pop the keyboard every time someone opens the menu.

2. Proposed change

2.1 Behaviour

  1. Entry point. Below md (< 768px), the header gets a Search icon button (lucide Search, IconButton size="lg", aria-label="Search") at the start of the right-hand cluster, just before the account pill. It is hidden at md+, where the header field already exists.
  2. Sheet. Tapping it opens a full-screen sheet built on the existing FullScreenDialog atom (100dvh, bg-surface). The title row reads Search and has the shared × close (44px tap target). Below it, in order:
    • the field: full width, h-11, leading search glyph, 16px text, placeholder “Search…”, no ⌘P hint. It has the same combobox ARIA as the desktop field and is focused when the sheet opens, so the keyboard comes up.
    • a status row, shown only once the trimmed query is non-empty: the result count (“N result(s)”) on the left and the existing Show completed CheckboxField on the right. On touch the count moves here from the desktop footer.
    • the results region: fills the rest of the height, overflow-y-auto overscroll-contain, with the safe-area inset as bottom padding. It holds the same Tasks / Stories / Wiki groups, the same ranking, the same cap of 8 and “+N more — keep typing” line, and the same empty and no-match messages as desktop.
  3. Rows. Rows use the full sheet width and a touch density: min-h-11 (44px), gap-3, py-2. Title, subtitle, story ref and kind badge are unchanged. Completed rows keep opacity-60. The first result keeps the active ring, because the keyboard’s Go key (Enter) opens it, exactly like ↵ on desktop.
  4. Scrolling. The results render inside the dialog content, not in a portalled popover, so the dialog’s own scroll lock doesn’t block them. Dragging the results list blurs the field, which dismisses the keyboard (the same behaviour as native iOS and Android search screens). This lets rows that were behind the keyboard scroll into view. The query and results stay. Tapping the field again brings the keyboard back.
  5. Choosing a result navigates exactly as today (a task goes through navigateToTaskAndFocus, a story or wiki page through history.pushState), then closes the sheet and clears the query.
  6. Closing without choosing. ×, the Android back gesture that Radix maps to Escape, or a hardware Esc closes the sheet and clears the query and Show completed (the existing closeDropdown semantics). The next open starts empty.
  7. The drawer loses its search field. ShellMobileNav no longer renders SearchBox. Its “close on arrival” rule keeps working for module-nav links.
  8. ⌘P below md. If the viewport is narrow (a desktop browser window under 768px, or an iPad with a keyboard), ⌘P opens the sheet instead of focusing a hidden field. Only one listener ever claims the key, as today.
  9. Desktop is unchanged: the header field, the anchored popover, keyboard hints, the popover width, and the shell-searchbox--open-with-results visual baseline.

2.3 Component plan

Teal = new or extracted. Both surfaces render the same rows and share one piece of combobox logic, so the desktop and mobile results can’t drift apart (see the frontend-architecture skill).

Adds density: 'compact' | 'touch'. compact is today’s markup, pixel for pixel: checkbox row at the top right, footer with key hints and count. touch gives min-h-11 gap-3 py-2 rows, a status row with the count on the left and the checkbox on the right, and no key-hint footer. The row styling belongs in a co-located search-results-list.styles.ts, following the app-shell.styles.ts pattern.
components/shell/search-results-popover.tsx Becomes a thin Popover.Portal / Popover.Content wrapper around <SearchResultsList density="compact" />. The outside-click and autofocus handling stays here.
components/shell/mobile-search.tsx (new) MobileSearch is the header trigger plus the sheet. Open state is !isDesktop && useSearch().open. The trigger calls openDropdown, and onOpenChange(false) calls closeDropdown. onOpenAutoFocus prevents the default and focuses the field (otherwise Radix would focus the × first). The results region has onTouchMove, which blurs the field if it is focused. It registers useGlobalSearchShortcut(openDropdown, !isDesktop). Input: enterKeyHint="go", the same role="combobox" and aria-* wiring and the same accessible name as the desktop field, and its own listbox id (global-search-results-mobile) so ids never collide.
components/shell/search-box.tsx Drop the placement prop and the 'mobile' branch. It is now desktop-only and uses useSearchCombobox. Keep the isDesktop gate on the popover’s open. This matters: the store’s open flag is shared, so without the gate, opening the mobile sheet would also open a popover anchored to the hidden header field.
components/shell/app-shell.tsx Put the right-hand cluster in a flex items-center gap-1 wrapper containing <MobileSearch /> (md:hidden) and then <InstanceMenu />.
components/shell/shell-mobile-nav.tsx Remove <SearchBox placement="mobile" … /> and its import. Update the doc comments that mention the drawer’s search field and closing on a search result, and the onOpenAutoFocus comment, whose reason (the search field) goes away. Whether that handler stays is up to the implementer: without it Radix would focus the first switcher link.
lib/hooks/use-media-query.ts Doc comment only: it now picks between the header field and the mobile sheet.
// mobile-search.tsx — the shape (not final code)
export function MobileSearch() {
  const isDesktop = useMediaQuery(DESKTOP_QUERY);
  const { open } = useSearch();
  const { openDropdown, closeDropdown } = useSearchActions();
  const inputRef = React.useRef<HTMLInputElement>(null);
  const combobox = useSearchCombobox({ inputRef });        // select() already calls closeDropdown
  useGlobalSearchShortcut(openDropdown, !isDesktop);

  return (
    <>
      <IconButton size="lg" aria-label="Search" className="md:hidden" onClick={openDropdown}>
        <Search size={18} />
      </IconButton>
      <FullScreenDialog
        open={!isDesktop && open}
        onOpenChange={(next) => { if (!next) closeDropdown(); }}
        title="Search"
        closeLabel="Close search"
        onOpenAutoFocus={(e) => { e.preventDefault(); inputRef.current?.focus(); }}
      >
        {/* field · status row · <SearchResultsList density="touch" …/> in a
            flex-1 overflow-y-auto region whose onTouchMove blurs the field */}
      </FullScreenDialog>
    </>
  );
}
Why the scroll fix is structural: don’t “fix” this by adding the popover as a scroll-lock shard or changing modal. Rendering the list inside the dialog content is what fixes it, because the only element Radix leaves scrollable is the content node. Don’t nest a Popover inside the sheet.

4. Acceptance criteria

  • At < 768px the header shows a Search icon button before the account pill. At ≥ 768px it is absent and the header field is unchanged.
  • Tapping it opens a full-screen “Search” sheet (FullScreenDialog) with the field focused. The field is 44px tall, at least 16px text, with no ⌘P hint.
  • Results fill the sheet’s width (≥ 90% of the viewport), rows are ≥ 44px tall, and grouping, ranking, badges and the 8-per-group cap with “+N more — keep typing” match desktop.
  • With more results than fit, the results region scrolls by touch and wheel, and the last result can be reached and tapped.
  • Dragging the results blurs the field (dismisses the keyboard) without closing the sheet or clearing the query.
  • The status row (count on the left, Show completed on the right) appears only when the query isn’t empty. On touch there is no key-hint footer.
  • Choosing a task, story or wiki result navigates exactly as today, then closes the sheet. The next open starts empty.
  • × / Esc closes the sheet and clears the query and Show completed.
  • The hamburger drawer no longer contains a search field.
  • ⌘P / Ctrl P opens the sheet on a narrow viewport and focuses the header field on a wide one. Only one listener is active.
  • Only one results surface is ever open: the desktop popover never opens while the viewport is narrow.
  • Desktop rendering is pixel-identical: the shell-searchbox--open-with-results baseline is unchanged and e2e/global-search.spec.ts passes unmodified.
  • The tests in §3 exist and check is green. The demo doc follows the showboat evidence rules.

5. Out of scope / open questions

  • Out of scope: any change to matching or ranking, the cap, desktop layout, a clear-text (⊗) button in the field, recent searches, wiki body search, and making the sheet a history entry (so browser Back would close it rather than leave the page).
  • Open, to verify on a real iPhone: iOS Safari only raises the keyboard for a focus() made inside the tap’s user gesture. Radix’s onOpenAutoFocus runs during React’s synchronous commit of the click, which normally counts, but Playwright can’t prove it. If the keyboard doesn’t come up on device, the fallback is to focus the field directly in the trigger’s onClick after flushSync(openDropdown). Record the outcome in the react or shadcn-ui skill.
