ALF-270 — Refactor module switcher

RefinementFrontend / shell Replace the five-word segmented control with an icon switcher, and give the sidebar back the width it grew to fit the words.

Context / problem

The module switcher (frontend/components/shell/view-switcher.tsx) sits under the alfred wordmark in the desktop sidebar's top block, and again in the mobile hamburger drawer (shell-mobile-nav.tsx). It is a segmented control with one word per module: Tasks · Code · Reader · Wiki · Comms. Each new module has pushed it past its budget, and the fix each time has been to widen the whole sidebar:

TicketSegmentsFixSidebar
ALF-2193fill container, flex-auto + min-w-0224px (md:w-56)
ALF-2334type 14→13px, padding cut256px (md:w-64)
ALF-2615widen, then widen again272px → 280px (md:w-70)

So the switcher is wide and wordy, and it also costs the main pane 56px on every screen. A sixth module would repeat the cycle. The ticket asks for one of two directions: icons when unselected, the word when selected, or icons all the time, with the open module's name shown in nearby negative space. It asks for the spec to be interactive so the choice can be made by trying both.

Settled with the ticket owner before writing: the name goes in the sidebar's top block (the wordmark row), not in the header bar. The sidebar shrinks back once the switcher is compact. This spec recommends one design with full acceptance criteria. The playground lets the owner overrule it in PR comments.

What the playground shows

  • Both A styles fit at 224px, but A · icon + word only just fits. Measured in Chromium with Reader active, the icon-and-"Reader" segment is 73px wide and the other four cells shrink to 25px, against the 24px a 16px icon and its padding need. That is the 1px of slack ALF-261 had before it clipped. A sixth module would break it. The fit line reports "cramped" when an icon cell drops under 24px. B's cells are 35px at 224px.
  • A moves its targets. The active segment is wider, so switching from Tasks to Wiki slides Code and Reader sideways. Every icon's position depends on which module is open, and you can't click from muscle memory. You can see this by clicking back and forth.
  • B has fixed geometry. Five equal cells, so every icon stays in the same place in every module. Adding a sixth module narrows every cell by a few px and never overflows.

Decision: Variant B, name at the right edge of the wordmark row, 224px

Build B, right-edge placement (confirmed by the ticket owner in PR review). Five icon-only segments at equal width, the active one raised and tinted in its module accent. The open module's name sits at the right edge of the wordmark row, opposite alfred, in that module's accent colour, with no separator. The sidebar and the mobile drawer go back to 224px (w-56).

Why B over A:

  1. Stable targets. A switcher is clicked many times a day, so fixed positions matter more than anything else. A reflows on every switch. B never does.
  2. It scales. A's active segment must fit the longest word ("Reader") next to N−1 icons, and that budget shrinks with each module. A · icon + word already has only 1px of slack at 224px. B needs 24px per icon and has 35px, so six modules would still fit (about 29px each).
  3. It uses empty space. Everything to the right of the wordmark is empty today. Right-aligning the name puts it on the same right edge as the switcher and leaves alfred standing alone.

Tradeoff: in B, the name and the icon you clicked are in different rows. The shared accent colour links them: the raised icon and the name are the same hue, and no other element in the block uses it.

The owner considered the "after the wordmark" placement (alfred / Tasks) and chose the right edge instead. The playground still offers both.

Every state of the chosen design

One frame per active module at 224px, plus the Comms badge when the queue is non-empty (it sits on the Comms icon's top-right corner, overlapping it slightly, as it does today) and the hover state.

Proposed change

1. A shared module-icon table

The palette already maps modules to icons in command-palette.tsx (ICONS: tasks: ListTodo, code: Code2, comms: MessagesSquare, reader: BookOpen, wiki: Library). Move those five into a table next to MODULE_ACCENT, following the "one table per module fact" rule that MODULE_ACCENT set in ALF-219, so the switcher and the palette can't disagree.

// frontend/lib/module-icons.ts   (new — kept out of lib/modules.ts so that file stays React-free)
import { BookOpen, Code2, Library, ListTodo, type LucideIcon, MessagesSquare } from 'lucide-react';
import type { ModuleId } from '@/lib/modules';

export const MODULE_ICON: Record<ModuleId, LucideIcon> = {
  tasks: ListTodo, code: Code2, comms: MessagesSquare, reader: BookOpen, wiki: Library,
};

// command-palette.tsx ICONS then spreads it:  { ...MODULE_ICON, inbox: Inbox, … }

The table also needs the display name, which is SEGMENTS[].label today. Add a MODULE_LABEL: Record<ModuleId, string> to lib/modules.ts (it's plain data). The switcher's aria-labels and the wordmark-row name both read from it.

3. The active-module name in the wordmark row (B)

Add a new client component, ActiveModuleLabel, in components/shell/active-module-label.tsx. It reads activeModule(usePathname()) and renders MODULE_LABEL[current] in MODULE_ACCENT[current].text at text-[13px] font-medium, baseline-aligned with the serif wordmark. There is no separator. AppShell (a Server Component) and the drawer each wrap their wordmark in a flex items-baseline justify-between gap-2 row, so the label sits at the row's right edge, in line with the switcher's right border.

  • It is plain text, not a link. The wordmark keeps its only job (back to capture).
  • The name is announced as plain text. The switcher's aria-current stays the programmatic source of truth.
  • min-w-0 truncate on the name is the floor. At 224px the longest name ("Reader") has more than 100px free.

4. Sidebar and drawer width: 280px → 224px

Change app-shell.tsx md:w-70 to md:w-56, change shell-mobile-nav.tsx w-70 to w-56 (its comment says it matches the sidebar), and change the story frame in view-switcher.stories.tsx to w-56. Replace the three-ticket width history in those comments with one line: the width is 224px, the switcher is icon-only so it has no label budget, and the module navs set the width (they fit at 224px before ALF-233). The implementer should check the nav with the longest label ("Needs human action" in ProjectNav) at 224px in the running app. If it clips, pick w-60 and say so in the PR.

Acceptance criteria

  • The desktop switcher shows five icon-only segments in the order Tasks, Code, Reader, Wiki, Comms, using the lucide icons ListTodo, Code2, BookOpen, Library, MessagesSquare. No visible words.
  • Each segment is a link with an accessible name (aria-label) and a title equal to the module name.
  • All segments have equal width, and no segment moves when the active module changes.
  • The active segment is raised (bg-surface + shadow) and its icon is in its module accent (amber, teal, green, violet, blue). Inactive icons are muted and turn foreground on hover.
  • (B) The wordmark row shows alfred on the left and the active module's name right-aligned (no separator), with the name in the active module's accent and its right edge in line with the switcher's, in the desktop sidebar and in the mobile drawer. The name is not a link. The wordmark still links to /.
  • The Comms queue badge still appears on the Comms segment's top-right corner when the count is above zero, and is not clipped.
  • The desktop sidebar and the mobile drawer are 224px wide (or 240px, with the reason given in the PR, if a module nav clips at 224).
  • MODULE_ICON is the only source of the module icons. The ⌘K palette uses it.
  • Switching modules is still a ViewLink pushState (no reload), and the mobile drawer stays open across a switch.
  • The ALF-219/233/261 width-fitting comments are removed or replaced with the current rationale.
  • check is green: the updated unit, E2E, and rebaselined snapshot tests pass, and there is a demo doc per the showboat skill.

Out of scope / open questions

  • A styled tooltip. There is no tooltip atom yet, so this spec uses the native title hover hint. A real tooltip is a separate atom ticket.
  • Keyboard shortcuts per module (for example ⌘1–⌘5) would fit icon segments well, but they are new behavior and out of scope here.
  • Moving the switcher to the header bar was considered and rejected with the ticket owner.
