ALF-359 — Log the session URL back to the ticket

A story’s detail view gets a Sessions list: every Claude Code session that worked on the story, labelled by lane and start time, each one opening that session. The link shows up seconds after the session’s first prompt.

Not doing

Working detail

Everything below is for the implementing agent. Approving needs only what’s above.

Context

The ticket asks for “a hook that logs the session URL back to the ticket”. Most of that already exists. The session-ledger recording hook (ALF-310, tools/session-ledger/src/hook/, wired in .claude/settings.json on SessionStart and Stop) POSTs to /api/code/sessions/record, which writes a code_sessions row through record_code_session (migration 0050). That row carries session_id (session_…, so the URL is https://claude.ai/code/<session_id>), repo, and ref, which stop.ts takes from the launch prompt’s leading ALF-nnn.

Two gaps remain. (1) Timing: ref arrives only with a Stop write, after the first turn ends, and a refinement or implementation turn can run for a long time. (2) Display: nothing in the frontend reads code_sessions; the story detail (components/code/story-detail-modal.tsx) shows only PR links. A third, smaller gap: launch_lane is backfill-only (inferred from the PR’s alfred block), so a live session has no lane to label it with.

The human settled scope in the refinement session: record on the first prompt (D1), list every session (D2), stories only (D3).

Decision records

D1Record on the first prompt · settled

A new UserPromptSubmit registration runs the same CLI with event prompt. Its write carries the prompt, its skills and its ref, which are the fields a Stop would send for them. record_code_session already freezes the first recorded prompt and fills ref only while it is null, so the later Stop writes leave them alone. Considered: Stop-only (no change); a SessionStart write (no prompt exists yet at that point).

Consequence: this write must also send skills, because the prompt freezes with whatever skills come with it (0050’s recorded-wins rule). A prompt write without them would lose the skills for good.

D2Every session, labelled · settled

Reruns, abandoned refinements and review sessions are all history worth reaching. Considered: the latest session per phase, or the latest only.

D3Stories only · settled

Epic sessions are recorded against the epic ref already, so a later ticket can surface them in epic-spec-modal.tsx by reusing D8’s selector.

D4Placement · proposed

Between Notes and Spec in both layouts (P1). The list reads as history, below the actions and above the long spec body. Considered: links inline in the header beside the PR links (crowds out with three or more sessions); a section in the footer controls area (that region holds controls, not links). The rows reuse PrLink’s treatment (accent-blue text, ExternalLink icon), so a session link reads as the same kind of thing as a PR link.

D5Realtime on code_sessions · proposed

Launching opens claude.ai in another tab, and the alfred tab stays put, so no navigation reconcile fires. Without realtime, D1’s early write wouldn’t reach an open board. Considered: fetching on modal open (breaks the data-flow skill’s rule against component fetches); a navigation reconcile only (misses the case above). Payload cost is small: Postgres leaves unchanged TOASTed columns (prompt, session_record) out of an UPDATE, and the store keeps only the slim columns (deliveredColumns).

D6Lane from the prompt · proposed

Every launch builder in frontend/lib/code/links.ts opens its second paragraph with a distinct sentence. The record route classifies any write that carries a prompt with a new pure laneOfPrompt and adds launch_lane to the RPC’s row. The hook stays dumb: it can’t import frontend/, as its import-graph test enforces. In SQL, launch_lane joins the platform-owned class: the hook fills it while null, and on a recorded row the backfill overwrites it only with a value. The backfill’s lane comes from the PR, so it is the more authoritative source and still wins. Considered: no lane, all rows labelled “Session” (fails D2’s label); classifying in the hook (it would need a copy of the builder strings with no test tying them together).

Implementation decisions

D7 · First prompt only, and only after a recorded start

UserPromptSubmit fires on every prompt. The hook sends a write only when the session’s start state file exists (readState non-null) and no <session>.prompted marker sits beside it. It writes that marker before POSTing, so a slow first prompt can’t race a second. With no state file (a resumed or re-provisioned container), it sends nothing, so a later prompt like “ok, go ahead” can never become the frozen launch prompt; the Stop path heals from the transcript as it does today.

D8 · A session belongs to a story by ref and repo

code_sessions.ref has no FK and no project. Match ref === story.ref and repo === `${story.repo_owner}/${story.repo_name}`, so a ref-shaped prompt in another repo never shows up on this ticket.

D9 · Silent stdout on UserPromptSubmit

On UserPromptSubmit, a hook’s stdout on exit 0 is injected into the model’s context. The CLI already prints nothing outside --dry-run; a test must pin that for the prompt event.

Behaviour

Hook (prompt event)

  • The gate is unchanged: a cse_ remote id, plus ALFRED_BASE_URL unless it is a dry run.
  • Reads prompt from the hook’s stdin JSON. A missing or empty prompt logs PromptMissing and sends nothing.
  • The body is {event:'prompt', session_id, repo, prompt, skills, ref?, warnings:[]}. repo comes from the state file and skills from skillPathsIn(prompt) resolved at the state’s base_sha (the same code as stopBody; extract a shared helper). ref uses the same refOf rule as the stop and is omitted when absent.
  • A failure is one line in hook.log, exit 0, no output.

List

  • Sort by session_created_at descending; nulls go last, then session_id as a stable tiebreak.
  • Time: browser-local, Intl.DateTimeFormat(undefined,{month:'short',day:'numeric',hour:'numeric',minute:'2-digit'}). Reuse an existing formatter in frontend/lib if one matches. A null time shows the label alone.
  • Each row is <a href target=_blank rel=noreferrer> whose accessible name is the label plus the time.
  • Realtime INSERT/UPDATE upserts by session_id, keeping only the slim columns. Rows with a null ref are ignored. DELETE removes the row.

Acceptance criteria

  • An alfred cloud session’s first prompt creates or updates its code_sessions row with ref, prompt (recorded), skills and launch_lane before the turn ends.
  • Later Stop writes leave that prompt, those skills and that ref unchanged.
  • A second prompt, or any prompt with no start state file, sends no write.
  • The prompt event prints nothing and exits 0, including when the POST fails or times out.
  • Each launch builder’s prompt classifies to its lane; an unrecognised prompt gives null.
  • A backfill with a lane overwrites a recorded lane; a backfill with null keeps it.
  • The story detail lists every session for the story’s ref and repo, newest first, labelled per the lane table with its local start time, each opening https://claude.ai/code/<id> in a new tab. This holds in both the dialog and the phone sheet.
  • With no sessions, the Sessions section is absent.
  • A session recorded while the modal is open appears without a reload.
  • Epic sessions don’t appear on any story.

Review focus

  • Same ref recorded from a different repo → not listed.
  • A realtime UPDATE omitting unchanged columns → the row’s lane and time are kept, not blanked.
  • An empty or missing stdin prompt → logged, no POST, exit 0.
  • A null session_created_at → the label alone, sorted last.
  • The first-prompt POST fails → the first Stop still records the prompt, skills, ref and lane.

The record route test checks lane injection. Store tests cover the seed, the selector filter/sort and the realtime upsert (with an omitted column).
  • RTL + Storybook: session-links in each P1 state and both layouts.

Demo evidence

Follow the showboat skill’s evidence rules: a screenshot of the story detail with sessions (via the mock backend), plus exec output of a --dry-run prompt event showing the body. Keep the hook silent outside dry-run.

Out of scope & risks

  • Status (running/idle) isn’t recorded by the hook, and a live poll of claude.ai is out of reach from the app.
  • Confirm while building: the UserPromptSubmit stdin field is prompt, and it matches the transcript’s first user message (if not, the later Stop’s prompt is ignored, which is harmless).
  • Risk: prompt-copy edits in links.ts silently break lane labels; the round-trip test is the guard.
